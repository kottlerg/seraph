A platform-floor and scale patch over v0.1.1: kernel and userspace address-space randomization,
IOMMU DMA confinement on both architectures, a hardware baseline enforced at boot, a redesigned
capability space with 64-bit handles, and fixed in-tree ceilings replaced by bounds sized from
the machine's RAM, CPUs, and devices.

---

## Highlights

- Address-space randomization: the kernel image base and the physical direct-map base are
  randomized at boot from a firmware entropy source, with a deterministic fallback and a
  `mkdisk --no-kaslr` override; every userspace binary is a position-independent executable
  loaded at a per-spawn random base with its RELRO span sealed read-only; and each process's
  stack, TLS, IPC buffer, heap, and reservation arena are placed at random.
- IOMMU DMA confinement: every DMA-capable driver maps its buffers through a devmgr DMA
  capability, and IOMMU driver processes confine each device to its own domain, `iommu-vtd` on
  x86_64 and `iommu-riscv` on riscv64. A driver's memory returns to the pool only once its
  device's DMA is confirmed stopped, a frame lent to it only once its transfer has completed or
  the device is stopped, and physical addresses are withdrawn from every process but devmgr and
  the IOMMU drivers. Without an IOMMU, devmgr serves every driver unconfined.
- Hardware baseline enforced at boot: [platform-requirements.md](../platform-requirements.md)
  classifies every CPU and platform feature per architecture, and the kernel halts with a
  diagnostic naming a missing required feature (x86-64-v3, SMEP/SMAP, XSAVE, RDRAND/RDSEED on
  x86_64; Sstc and the Svpbmt, Svinval, and Svnapot paging extensions on riscv64). The timer
  tick uses Sstc `stimecmp` on riscv64 and TSC-deadline mode on x86_64 where available; riscv64
  selects Sv39, Sv48, or Sv57 and x86_64 4- or 5-level paging at boot.
- Capability space redesign: rights are numbered per capability type; the CSpace directory is a
  two-level radix tree with no per-CSpace slot quota, grown from memory its holder donates;
  capability handles are 64 bits (a 32-bit slot index and a generation); revocation is batched
  and restartable; and every CSpace holds a reserve of slots for IPC capability transfer.
- Bounds sized to the machine: [limits.md](../limits.md) catalogues every in-tree bound and
  classifies it against a hardware-realistic ceiling. Nothing in the kernel's memory management
  stops the boot on RAM size, CPU count, or memory-map or aperture counts; the kernel sizes its
  CPU sets, per-CPU storage, interrupt tables, and boot handover tables from the hardware
  (`MAX_CPUS` is an 8192-CPU sanity ceiling no structure is sized from); memmgr bounds its
  tables by RAM; and procmgr, svcmgr, vfsd, devmgr, fatfs, and the ruststd thread reaper grow
  theirs on demand.
- Whole-VM snapshot safety: on x86_64 a VMGENID generation change forces every per-CPU
  generator to reseed before its next output; on riscv64 a reseed time budget bounds the output
  replayed after a resume.
- Priority policy: thread creation is placed by `SchedControl` authority, and every process
  starts at the priority and band its service recipe or spawner names (`priority =` and
  `sched_max =` in `.svc` recipes; `CommandExt::priority` and `sched_max` in ruststd).
- Storage and devices: vfsd discovers role partitions on every block device; disks with
  4096-byte logical blocks boot; every PCI function of every ECAM window is enumerated; a
  shared `INTx` line serves every device on it, level-triggered; and devmgr serves a driver
  only once it reports ready, withdrawing a driver that dies or hangs.
- Kernel hardening: a fault on a user pointer returns `InvalidAddress` instead of halting the
  kernel; x86_64 kernel entry clears AC, DF, and TF and swaps GS on every ring-3 transition,
  and sets `CR4.UMIP`; the capability lookup is hardened against speculation; every kernel
  stack has an unmapped guard page below it; a retype over a page a process maps is refused;
  RAM is zeroed before it reaches userspace; and kernel virtual addresses stay off the
  userspace-readable console. Scheduler, sleep-list, binding, and object-lifetime races are
  fixed.

## Components Shipped

**Kernel** (`core/kernel`) — The kernel is a static PIE whose image slide and direct-map base
the bootloader randomizes; it prints addresses only on the serial-only console path, an audit
of its cross-boundary output surface is recorded in
[cross-boundary-disclosure.md](../../core/kernel/docs/cross-boundary-disclosure.md), and
watchdog and fatal dumps keep kernel virtual addresses off the mirrored console. A boot-time
`cpu::verify_baseline()` enforces the platform floor and sets `CR0.WP`. The timer arms Sstc
`stimecmp` on riscv64 and TSC-deadline on x86_64, with periodic-APIC fallback; the paging depth
comes from `satp` on riscv64 and `CR4.LA57` on x86_64; Svpbmt, Svinval, and Svnapot back
uncacheable mappings and range shootdowns. Capabilities carry per-type rights, live in a
two-level radix CSpace directory with no slot quota, are named by 64-bit handles, and revoke in
restartable batches; revoking an Mmio or IoPort capability withdraws the mappings and port
bindings made through it. The bodies a syscall creates without a Memory capability are funded
from a CSpace the call names, and the CSpace registry is sized from RAM. Each Interrupt
capability binds on its own, so a wired line serves up to 64 bindings, and `SYS_IRQ_REGISTER`
takes a trigger and polarity mode. The buddy allocator's free lists live in the free blocks,
and boot tables, per-CPU slabs, CPU sets, interrupt tables, the `InitInfo` region, and each
thread's extended-state area are sized from the hardware. The sleep list is a deadline heap,
wait sets are caller-sized, death events carry a full `u64` correlator, and init's CSpace is
freed at init's reap. A user-copy fault returns an error. The kernel adds x86_64 entry
hardening and UMIP, a speculation-hardened capability lookup, a guard page below every kernel
stack and stack painting to measure their depth, the refusal of a retype over a mapped page,
and the zeroing of drained RAM and bootloader reclaim ranges. `SYS_CAP_INFO` gains
`CAP_INFO_MEMORY_MAPPINGS`, `CAP_INFO_SOLE_REFERENCE`, and `CAP_INFO_ASPACE_TERMINAL_FAULT`,
`SYS_SYSTEM_INFO` gains the user VA top, the stack high-water marks, the Thread retype size,
and the live CSpace count, and a new Memory right, `RIGHTS_MEM_PHYS`, gates physical-address
disclosure. Thread creation takes a `SchedControl` capability and priority, and init runs at
priority 30. Races in the sleep list, stop and teardown, the per-CPU scheduler, affinity and
IOPB updates, cross-CPU dispatch, and fault, death-observer, and IRQ bindings are fixed.

**Bootloader** (`core/boot`) — Selects the KASLR slide and direct-map base from an
`EFI_RNG_PROTOCOL` draw kept separate from the pool seed (a DTB `/chosen/rng-seed` reader is
the fallback), applies the kernel's relocations, and pre-locates init's `.rela.dyn`. It
discovers the QEMU VMGENID buffer, the riscv64 timebase and hart extensions from ACPI RHCT or
the DTB, and the PLIC source count; negotiates the riscv64 paging mode with a `satp`
write-probe; and enables 5-level paging on x86_64 when the CPU reports LA57. Its boot tables,
the CPU-id array (now in pages of its own), and the aperture seeds are sized from the platform,
and steps 6 and 7 are redone when the memory map outgrows its array. MMIO apertures are clipped
off RAM, and the handoff stack gets an unmapped guard page and is painted for depth
measurement. Its link flags come from `cargo xtask build` and its own `build.rs`, so a worktree
nested under a checkout builds.

**Core services** (`services/`) — procmgr loads every binary it spawns as a PIE at a random
base with RELRO sealed, places each process by the priority policy, takes argv and env in a
Memory capability the caller sizes, grows its process table and death queues, and holds a
`CREATE_DMA_HOLD` child's death notice until the creator's release token releases it; a failed
create releases everything it acquired. memmgr bounds its process table, free pool, arena, and
page tables by RAM, accepts donations from procmgr alone, returns a reclaimed frame to the pool
only once its retained capability is the sole reference, and names grants by opaque region ids
instead of physical bases. svcmgr gates the handover on init's authority, passes bootstrap slot
lists over as many rounds as they need, resolves authority-bearing names only through recipe
seeds, grows its tables, and gives each service a windowed restart budget. init-logd keeps a
sender's late-registered name across the handover, evicts unnamed senders before named ones,
and holds its history in a 16 KiB ring. vfsd gates `MOUNT` on a verb bit, grows its mount tree
and partition table, and releases everything a failed mount acquired. pwrmgr bounds its ACPI
reads and replies to a failed shutdown or reboot.

**Drivers** (`services/devmgr`, `services/drivers/`) — devmgr enumerates every PCI function of
every ECAM window, delivers every BAR a VirtIO device's register regions name, serves a driver
only once it reports `DRIVER_READY`, and withdraws a driver that dies or hangs in setup. It
gives every device on a shared `INTx` line its own Interrupt derivation, with a trigger and
polarity mode derived from the MADT's overrides. A new DMA endpoint maps each driver's buffers;
the `iommu-vtd` and `iommu-riscv` drivers over `iommu-core` program VT-d and the RISC-V IOMMU,
and devmgr stops a withdrawn device's bus mastering and resets it before releasing its memory.
virtio-input, framebuffer, and the whole-disk block query are gated on verb bits; virtio-core
validates every device-written completion; virtio-blk reports its logical block size through
`BLK_GET_GEOMETRY` and resets the device on a lost request; cmos reads the century from the
FADT.

**Storage** (`services/fs`, `services/vfsd`) — vfsd parses the GPT of every block device and
resolves roles over the union of their partitions, in each disk's block size. fatfs gives each
`FS_OPEN` its own capability and reclaims the opens of a client that dies without `FS_CLOSE`,
never refills a cache page a client still maps, settles a failed remove or rename by what the
device holds, deletes an entry's long-name run when it is removed by its short alias, and grows
its open-file tables and its cache.

**Runtime** (`runtime/ruststd`) — The std userspace targets are position-independent, and the
heap and reservation arena are placed at random in zones sized from the address space. Spawned
threads start at the process's initial priority, `std::thread::spawn` tops up the CSpace before
each spawn, and the thread reaper grows its slots and death queues. The main thread's stack
grows on demand to 2 MiB. `Condvar` and `Once` wake every queued waiter, `File` reads through
its own open, and `std::os::seraph` carries the ABI's retype-cost constants.

**Shared** (`shared/`, `abi/`) — `shared/process-layout` owns the per-process VA layout and its
random draws; `shared/elf` loads `ET_DYN` images with `RELATIVE` relocations and bounds-checks
every header read; `shared/crypto` refuses non-canonical Ed25519 public keys; the namespace
protocol never mints reserved rights bits and applies each entry's visibility to `NS_READDIR`;
the `shared/syscall` wrappers that can write behind a reference or start a thread on foreign
memory are `unsafe fn` with `# Safety` contracts; and a new `shared/death-set` crate holds the
death-queue set procmgr and svcmgr share.

**Userspace programs** (`programs/`) — The terminal spawns the shell at priority 5. A new
`relrofault` fixture checks RELRO enforcement, and every program and fixture has a README.

**Build and test tooling** (`xtask`, CI) — `cargo xtask lint-docs` checks the mechanical
documentation and file-header rules, including that the coverage-tier surface names resolve.
New host-driven boot tests are `test-kaslr`, `test-vmgenid`, `test-logd-reclaim`, and
`test-map-redo`; `ktest-timing` reports per-cell boundary-run timings against checked-in
baselines. `mkdisk` authors 4Kn images (`--block-size 4096`) and split data disks
(`--split-data`); `run` and `run-parallel` attach a second disk (`--second-disk`, with
`--second-disk-block-size` and `--second-disk-shared-line`), pin the x86_64 paging depth
(`--x86-paging`), and detach the IOMMU (`--iommu absent`), and `run-parallel --save-logs` keeps
every run's log. The default QEMU device set adds `virtio-rng-pci`, the machine's IOMMU, the
`edu` DMA test device, and, on x86_64, `vmgenid`. CI downloads QEMU once per run into a shared
cache, derives each cell's boot budget from its measured worst, and keeps every run's log. The
local boundary set is 16 and 128 CPUs on both architectures, and the release host runs add
release-profile boundary boots, four disk variations, and the no-IOMMU variant.

**Documentation** (`docs/`) — New [platform-requirements.md](../platform-requirements.md) and
[limits.md](../limits.md). The documents across the tree, and the source comments under
`core/`, `abi/`, and `shared/`, were audited against the code; summaries link their sources,
`## Summarized By` sections were rebuilt, and the documentation standards gain the grouping
scope and the design-intent rule. [coding-standards.md](../coding-standards.md) gains a
CPU-Count Width section; [testing.md](../testing.md) § Coverage tiers owes local host runs by
the CPU-count and memory surfaces a change touches; and the Branch and PR Workflow section of
[conventions.md](../conventions.md) defines the two-track pre-merge review and the per-scope
follow-up Issues.

## Breaking Changes

Every component named below ships in the one disk image, so an image consumer needs no
migration; code built outside the tree against v0.1.1 must be rebuilt against v0.1.2's `abi/`,
`shared/`, and `ruststd`.

- Hardware floor: the kernel refuses to boot on a CPU below the
  [platform-requirements.md](../platform-requirements.md) baseline, naming the missing feature.
  `cargo xtask run` passes a conforming CPU; a hand-built QEMU command line must select a CPU
  model that provides the required features ([build-system.md](../build-system.md) § QEMU and
  Firmware).
- Boot protocol (`BOOT_PROTOCOL_VERSION` 9 → 19): `BootInfo` gains the PIE init fields, the
  riscv64 timebase, hart-capability, and PLIC-source fields, the VMGENID address, and the KASLR
  direct-map base and flags; the CPU ids move to pages of their own, and the I/O APIC, boot
  module, aperture, and CPU bounds change. A bootloader and kernel must come from the same
  release.
- Init protocol (`INIT_PROTOCOL_VERSION` 13 → 16): `InitInfo` names up to 85 modules, its
  region is sized from the boot's descriptor counts (`init_info_memory_count` gives its page
  count), and every slot field is 64 bits. The kernel and init must come from the same release.
- Process ABI (`PROCESS_ABI_VERSION` 20 → 24): the `ProcessInfo` page address arrives in the
  entry register and the stack, TLS, and IPC-buffer addresses are creator-chosen fields (the
  fixed-address constants are removed); `ProcessInfo` gains `initial_priority`; every
  capability field is 64 bits; and argv and env live in their own pages after the `ProcessInfo`
  page. Userspace binaries must be rebuilt against v0.1.2's `abi/process-abi` and `ruststd`.
- Syscall contracts: capability handles are `u64`; the shared rights names (`RIGHTS_SEND`,
  `RIGHTS_MAP_READ`, and the rest) are replaced by per-type constants (`RIGHTS_EP_SEND`,
  `RIGHTS_MEM_MAP`, and so on); IPC sends carry full handles in the IPC buffer's capability
  block; `SYS_CAP_CREATE_THREAD` takes a `SchedControl` capability and a priority;
  `SYS_THREAD_SET_FAULT_HANDLER` takes the fault badge from the bound Endpoint capability and
  reserves arg2; `SYS_IRQ_REGISTER` takes a trigger and polarity mode in arg2; `MAP_READONLY`
  is renamed `MAP_FROM_CAP`; `CAP_INFO_MEMORY_PHYS_BASE` requires `RIGHTS_MEM_PHYS`, and an
  address-space retype mints `RIGHTS_AS_READ`, which `SYS_ASPACE_QUERY` requires, only from a
  Memory capability that holds it; `SYS_MEMORY_SPLIT` and `SYS_MEMORY_MERGE` act only through a
  Memory object's sole slot; a retype over a page any address space maps fails with
  `OutOfMemory`; and a CSpace's last `MSG_CAP_SLOTS_MAX` free slots are kept for IPC receive.
  Callers must use the v0.1.2 `abi/syscall` constants and `shared/syscall` wrappers
  ([core/kernel/docs/syscalls.md](../../core/kernel/docs/syscalls.md)).
- Service protocols (`PROCMGR_LABELS_VERSION` 2 → 9, `MEMMGR_LABELS_VERSION` 5 → 9,
  `SVCMGR_LABELS_VERSION` 4 → 10, `DEVMGR_LABELS_VERSION` 7 → 14, `VFSD_LABELS_VERSION` 1 → 2,
  `FS_LABELS_VERSION` 3 → 5, `BLK_LABELS_VERSION` 2 → 3, `LOG_LABELS_VERSION` 1 → 2): procmgr
  creates take priority and band fields and argv and env in a Memory capability; memmgr names
  grants by region id, and `RELEASE_MEMORY_CAPS` takes those ids; `FS_READ_MEMORY`,
  `FS_RELEASE_MEMORY`, and `FS_CLOSE` go to the per-open capability `FS_OPEN` returns; vfsd
  `MOUNT` requires `MOUNT_AUTHORITY`; devmgr's whole-disk query requires
  `BLOCK_DEVICE_AUTHORITY`; and svcmgr's bootstrap rounds carry a presence word. Clients must
  use the v0.1.2 `shared/ipc` labels.

## Known Issues

- On riscv64, a boot with no `virtio-rng` device (or other firmware `EFI_RNG_PROTOCOL` source)
  seeds the entropy pool from timing jitter alone, so early-boot entropy is thinner than on
  x86_64; the default QEMU boot set attaches `virtio-rng-pci` and is firmware-seeded. No S-mode
  hardware entropy source is wired up yet. Tracked by
  [#393](https://github.com/kottlerg/seraph/issues/393).
