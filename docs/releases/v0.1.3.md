A debugging and fault-reporting patch over v0.1.2: userspace debugging through per-class fault
handlers, thread memory access, and a GDB stub served over a debug port; crash reports for every
process that dies on a fault; asynchronous thread upcalls; and a scheduler split into a
strict-priority class and a weighted fair class.

---

## Highlights

- Userspace debugging: a thread's fault handler is bound per fault class (VM, exception, upcall),
  can be queried and copied to another thread, and a change of the binding while a fault is in
  flight redelivers the fault under the new one. A thread can be started suspended, a holder of
  `CONTROL` on a Thread capability can read and write the thread's memory, including its text,
  and a breakpoint or single-step reaches the exception handler on both architectures (the trap
  flag on x86_64, a `c.ebreak` planted at the computed successor on riscv64). The new `gdbstub`
  service debugs one process of a running system from host GDB over a `virtio-console` debug
  port (`cargo xtask run --debug-port <PORT> --debug-target <NAME>`).
- Crash reports: a process that dies on a fault leaves a marked crash-report block in the system
  log, written by the new `crashd` service, with the faulting thread's registers and stack walk,
  for the main thread and for every thread the runtime spawns. `cargo xtask symbolize --log`
  resolves the blocks of a serial log against the sysroot's binaries.
- Asynchronous upcalls: `SYS_THREAD_POST_UPCALL` marks an upcall pending on a thread, delivered
  through a third fault-handler class at the thread's next syscall return or, with
  `UPCALL_ANY_INSTRUCTION`, at an interrupt's return to user mode; `SYS_THREAD_SET_UPCALL_MASK`
  defers them.
- Scheduler classes: priorities 21 to 30 keep strict fixed priority, and priorities 1 to 20 share
  one weighted round-robin queue per CPU in which a thread's slice is its level in ticks; an
  idle CPU pulls a Ready thread queued behind a running thread on another CPU, and the runtime's
  spin mutex sleeps once a bounded spin is spent. Together they remove a livelock that hung the
  x86_64 release svctest boot.
- Instruction-fetch coherence on riscv64: the kernel makes every hart's instruction fetch see
  code written through a data path (`fence.i` and SBI RFENCE `remote_fence_i`) before an
  executable `SYS_MEM_MAP` or `SYS_MEM_PROTECT` and after a thread-memory write.
- The CSpace directory reaches the whole 32-bit index field of a capability handle, and init
  funds its own CSpace from its bootstrap arena.

## Components Shipped

**Kernel** (`core/kernel`) — Fault handlers bind per class (`FAULT_CLASS_VM`,
`FAULT_CLASS_EXCEPTION`, `FAULT_CLASS_UPCALL`), and the new `SYS_THREAD_GET_FAULT_HANDLER` (56)
and `SYS_THREAD_INHERIT_FAULT_HANDLER` (57) query a binding and copy one to another thread. A
change of a class's binding cancels the fault delivery in flight through the old one, and the
faulting thread delivers the fault again under the binding current when it next runs; a cleared
binding leaves the fault unhandled. `SYS_THREAD_START` takes `THREAD_START_SUSPENDED`, which
commits a configured thread `Stopped`. The handler of a VM fault can answer it with
`FAULT_REPLY_FORWARD`, which delivers it to the thread's exception handler with the forwarder's
reason word. `SYS_THREAD_POST_UPCALL` (58), gated on the
new Thread right `RIGHTS_THREAD_UPCALL`, and `SYS_THREAD_SET_UPCALL_MASK` (59) deliver and defer
upcalls as `FAULT_KIND_UPCALL`; a thread blocked in a syscall returns `Interrupted` to take one.
`SYS_THREAD_READ_MEM` (60) and `SYS_THREAD_WRITE_MEM` (61) copy up to `MAX_THREAD_MEM_COPY`
(4096) bytes to or from a thread's address space under `CONTROL`, a read-only page taking a write
only with `THREAD_MEM_TEXT` and a frame mapped once. On x86_64 a user `int3` delivers
`FAULT_EXC_BREAKPOINT` and the trap flag one `FAULT_EXC_DEBUG` per instruction. The scheduler
splits at `RT_PRIORITY_MIN` (21) into the strict-priority and weighted fair classes; an RT
thread queued on a CPU preempts a running fair thread at the next tick, and an idle CPU pulls an
unpinned Ready thread from a CPU running a non-idle thread, the pull re-deciding its rule under
both run-queue locks. The CSpace directory's root splits 128 direct, 64 indirect, 63
double-indirect, and 1 triple-indirect pointers, so `MAX_SLOTS_STRUCTURAL` reaches
4 294 967 264, and the root CSpace comes with one body page. The kernel prints why a user fault
went unhandled, with the handler's decline reason. riscv64 synchronizes instruction fetch on
every hart before executable mappings and after thread-memory writes. `SYS_MEM_PROTECT` keeps a
leaf's memory type, and the thread memory copy refuses a frame above the top of RAM, so neither
reaches device memory through the direct map.

**Core services** (`services/`) — The new `crashd` service receives each fault of a process
bound to it, logs one crash-report block, and declines the fault so the exit reason is
unchanged. procmgr owns the crash endpoint and the debug authority: it lists processes
(`LIST_PROCESSES`), attaches and detaches a debugger (`ATTACH_PROCESS`, `DETACH_PROCESS`),
registers every runtime-spawned thread (`REGISTER_THREAD`) under a crash badge of its own,
and restores the crash bindings when a debugger dies attached. It tells a debugger's binding by
the debugger tag (`DEBUGGER_BADGE_TAG`) under one rule at registration, restore, and
declaration, so a process that declares itself undebuggable (`DECLARE_NO_DEBUG`) stays so when
an attached debugger dies. crashd's watchdog bounds every attach of a fault's handling. The new
`gdbstub` service speaks the GDB remote serial protocol over the debug port: breakpoints,
single-step, registers, memory, an asynchronous break, the thread list, and detach. memmgr sends
a reason with every fault it refuses and forwards a page fault it cannot back to the thread's
exception handler. devmgr counts a DMA fault it has taken before a `TEST_DMA_FAULTS` query reads
the counts.

**Drivers** (`services/devmgr`, `services/drivers/`) — devmgr binds a `virtio-console` debug
port on both architectures, driven by a new virtio-console driver that serves the serial
protocol, declares itself undebuggable, and is handed only to a service seeded with
`devmgr.debug` (`DEBUG_PORT_AUTHORITY`).
The serial and virtio-input drivers delete every capability a request carries that they do not
keep; virtio-blk and virtio-input use checked conversions, and the VirtIO drivers program their
rings through `PciTransport::queue_set_rings`.

**Runtime** (`runtime/ruststd`) — Each spawned thread copies the spawning thread's fault-handler
bindings, registers with procmgr before its code runs, and a spawn whose fault-handler bind is
refused fails. Its memmgr calls repeat when a stop or an upcall interrupts them. `std`'s spin
mutex sleeps between attempts once a bounded spin is spent.
`ChildExt::main_thread_cap` returns a child's main-thread capability.

**Shared** (`shared/`, `abi/`) — New crates: `shared/crash-report` writes and parses the
crash-report block, `shared/gdb-rsp` implements the GDB remote serial protocol (`no_std`), and
`shared/riscv-step` computes a riscv64 instruction's successor for single-step. The ABI gains
the syscalls, rights, fault classes, and register offsets above, `CSPACE_BODIES_PER_PAGE`, and
`IOPORT_BINDING_TABLE_PAGES`; `ipc::VERB_BIT_MASK` widens to bits 58 to 63.

**Userspace programs** (`programs/`) — New `debugger` (breakpoints, single-step on both
architectures, an asynchronous break through an upcall), `deadline` (a deadline supervisor run
by usertest), and the `crashme` and `stackoverflow` crash fixtures; `debug-echo` exercises the
debug port.

**Build and test tooling** (`xtask`, CI) — `cargo xtask symbolize` resolves addresses in a
loaded ELF image and, with `--log`, every crash-report block of a serial log; `run-parallel`
writes that report beside each log it keeps. `run` and `run-parallel` gain `--debug-port` and
`--debug-target`, and `run-parallel` `--display framebuffer` and `--fail-also`; new boot tests
are `test-crash-report`, `test-debug-port`, and `test-gdb`. `cargo xtask build --component` and
`--debug` accept every crate the build knows. New commands check the project's conventions
(`commit-check`, `pr-check`, `review-check`, `review-ledger`, `issue-edit`, `issue-file`), keep an
orchestration batch's state (`orch`), and answer the assistant harness's hooks (`hook`); CI runs
`commit-check` on every pull request. The Rust toolchain moves to `nightly-2026-11-10`, and the
ktest timing baselines are rewritten on it.

**Documentation** (`docs/`) — [testing.md](../testing.md) § Coverage tiers defines a device
surface per driver and the device cells each owes, the framebuffer and debug-port cells among
them, and states the boundary-run times of the new baselines;
[fault-handling.md](../fault-handling.md) gains § Debugging;
[conventions.md](../conventions.md) § Release Production runs the release review, and the
pre-merge review is the two-agent review of § Branch and PR Workflow.

## Breaking Changes

Every component named below ships in the one disk image, so an image consumer needs no
migration; code built outside the tree against v0.1.2 must be rebuilt against v0.1.3's `abi/`,
`shared/`, and `ruststd`.

- Hardware floor: on riscv64 the kernel refuses to boot without the SBI RFENCE extension, which
  its instruction-fetch synchronization needs
  ([platform-requirements.md](../platform-requirements.md)).
- Init's CSpace: the root CSpace comes with one body page, and init funds its own CSpace from its
  bootstrap arena before it splits further. `INIT_PROTOCOL_VERSION` was not bumped for this
  (Known Issues); the kernel and init must come from the same release.
- Syscall contracts: the scheduler reads priorities 1 to 20 as fair-class weights, and only 21 to
  30 as strict priorities; a change of a fault-handler binding while a fault is in flight
  redelivers the fault under the new binding, and clearing it leaves the fault unhandled; on
  x86_64 a user `int3` delivers `FAULT_EXC_BREAKPOINT` to the exception handler instead of
  raising `#GP`; a thread blocked in a syscall can return `Interrupted` when an upcall is posted
  to it; `RIGHTS_THREAD` gains `RIGHTS_THREAD_UPCALL`
  ([core/kernel/docs/syscalls.md](../../core/kernel/docs/syscalls.md)).
- Service protocols (`PROCMGR_LABELS_VERSION` 9 → 12, `DEVMGR_LABELS_VERSION` 14 → 15): procmgr
  adds `REGISTER_THREAD`, `LIST_PROCESSES`, and `DETACH_PROCESS`; `ATTACH_PROCESS` requires the
  debug authority, takes an optional debugger watch, resolves a thread's crash badge to its
  process and thread, and returns the process badge and the thread's index; a debugger binds a
  listed thread's exception or upcall class under a badge carrying `DEBUGGER_BADGE_TAG` (bit
  62) with bit 63 clear; devmgr adds
  `QUERY_DEBUG_PORT_DEVICE`, gated on `DEBUG_PORT_AUTHORITY`, and `ipc::VERB_BIT_MASK` widens to
  bits 58 to 63. Clients must use the v0.1.3 `shared/ipc` labels.

## Known Issues

- An idle CPU's pull can leave a backlog on one CPU starved while another CPU stays above the
  imbalance threshold with no thread it can pull. Tracked by
  [#862](https://github.com/kottlerg/seraph/issues/862).
- `INIT_PROTOCOL_VERSION` was not bumped when the root CSpace's body pages went from 16 to 1, so
  an init that does not fund its own CSpace passes the version check and then fails its splits
  with `OutOfMemory`. Tracked by
  [#863](https://github.com/kottlerg/seraph/issues/863).
- The crash-report parser, which `cargo xtask symbolize` uses, refuses a `status` or `kind` value
  it does not know, although the block format lets a new value keep version 1; `symbolize` labels
  a block whose attach failed as an unnamed process. Tracked by
  [#864](https://github.com/kottlerg/seraph/issues/864).
- On the debugger and crash paths, a process's creator can declare the process undebuggable or
  register threads into it; `gdbstub` does not check that its own no-debug declaration
  succeeded; a failed `REGISTER_CRASH_SERVICE` reply leaves the crash service registered with no
  receiver; a `REGISTER_THREAD` call interrupted after procmgr received it leaves the thread
  registered while the runtime treats it as unregistered; the GDB protocol parser accepts a
  malformed `D;<pid>` or `qAttached:<pid>`; and a failure message init logs while it carves its
  CSpace is written before its serial console is up, raising `#GP` on x86_64 and lost on
  riscv64. Tracked by [#865](https://github.com/kottlerg/seraph/issues/865).
- A freshly spawned `std` thread can be killed on the first write to its demand-paged stack
  (`USERSPACE FAULT` #PF) when the page fault goes unserved; the kernel now logs why such a fault
  went unhandled. Tracked by [#794](https://github.com/kottlerg/seraph/issues/794).
- On riscv64, a boot with no `virtio-rng` device (or other firmware `EFI_RNG_PROTOCOL` source)
  seeds the entropy pool from timing jitter alone. Tracked by
  [#393](https://github.com/kottlerg/seraph/issues/393).
- Block I/O through virtio-blk pays a devmgr round trip for each transfer's `DMA_MAP` and
  `DMA_UNMAP`. Tracked by [#772](https://github.com/kottlerg/seraph/issues/772).
