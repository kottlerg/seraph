A device-interrupt and concurrency patch over v0.1.3: message-signaled interrupts on both
architectures (MSI and MSI-X with VT-d interrupt remapping on x86_64, the AIA's APLIC and IMSIC
in place of the PLIC on riscv64), data-driven driver binding in devmgr, timeouts and try-once on
blocking waits, multi-threaded services, and the class B lint set enforced across the workspace.

---

## Highlights

- Message-signaled interrupts: the kernel mints message-signaled targets (`SYS_IRQ_MSG_ALLOC`),
  a wired line is routed explicitly (`SYS_IRQ_ROUTE`), and on x86_64 devmgr turns VT-d interrupt
  remapping on when every remapping unit is handed over and on one PCI segment: the kernel
  switches to the remappable formats (`SYS_IRQ_REMAP`), and devmgr has the VT-d driver write each
  interrupt source's entry. The VirtIO drivers take MSI-X vectors, and devmgr writes the MSI-X
  table. On riscv64 a device's message reaches its hart's IMSIC file through a first-stage
  mapping in the device's IOMMU domain.
- riscv64 interrupt controller: the kernel drives the supervisor-level APLIC in MSI delivery mode
  and each hart's IMSIC file in place of the PLIC, which the kernel, the bootloader, and the boot
  protocol no longer carry. Every riscv64 QEMU launch gives the machine `aia=aplic-imsic` and its
  harts `ssaia=on,smaia=on`.
- Bounded waits: `SYS_IPC_CALL`, `SYS_IPC_RECV`, and `SYS_WAIT_SET_WAIT` take a `timeout_ms` in
  which `0` waits forever and any other value bounds the wait. `SYS_IPC_RECV`,
  `SYS_WAIT_SET_WAIT`, and `SYS_NOTIFICATION_WAIT` also take the `WAIT_TRY_ONCE` sentinel of
  `SYS_EVENT_RECV`, which never parks; `SYS_IPC_CALL` has no try-once value. Several threads can
  wait on one wait set. Client logging sends through a bounded call, so a logd that never
  answers delays its clients without wedging them.
- Concurrent services: procmgr, devmgr, and logd serve requests on worker pools, procmgr beside a
  dedicated reaper thread, and the runtime parks every lock on the thread's Parker.
- Data-driven driver binding: devmgr binds drivers from their declarations and the device
  records, serves every device class through one class query, and binds drivers on demand; the
  per-class queries and the test labels are retired.
- Logging: `seraph::log!` call sites carry log levels filtered by `SERAPH_LOG`, the log stream
  frames structured fields, and logd gains a query API over its slot table and history.
- Safer code and stacks: the workspace enforces the index, arithmetic,
  one-unsafe-operation-per-block, suppression-rationale, and class B lints; every user stack gets
  a four-page guard, the `lowuser` targets emit stack probes, and every riscv64 kernel frame is
  bounded at 2032 bytes.
- Tighter capability bounds: a mapped leaf records the rights of the capability that mapped it,
  so `SYS_MEM_PROTECT` and a `THREAD_MEM_TEXT` write cannot widen it past its grant.

## Components Shipped

**Kernel and bootloader** (`core/kernel`, `core/boot`) — `SYS_IRQ_MSG_ALLOC` (62) takes an
Interrupt capability carrying the new `RIGHTS_IRQ_MINT` and returns an unbound Interrupt
capability over one message-signaled target: a device vector of one x86_64 CPU, or an identity
in one riscv64 hart's IMSIC file. `SYS_CAP_INFO` reports its message address and data, and
`SYS_IRQ_REGISTER` binds it. A target is a minter-funded object anchored by its CPU's slot entry,
the routing table keeps the wired lines only, a device delivery runs under its CPU's delivery
gate, and a bound interrupt binding holds a counted reference on its Notification.
`SYS_IRQ_ROUTE` (63) fixes a wired line's target explicitly, and `SYS_IRQ_REMAP` (64), allowed
only while no interrupt source exists, switches the formats the kernel programs and hands out to
an IOMMU's interrupt remapping; once it is on, the x86_64 kernel emits remappable-format
messages and I/O APIC entries, whose remapping-table entries the IOMMU driver writes. The riscv64
kernel drives the APLIC and IMSIC in place of the PLIC. The blocking calls above take their
timeouts as the Highlights state: an expired `SYS_IPC_CALL`, `SYS_IPC_RECV`, or
`SYS_WAIT_SET_WAIT` returns `WouldBlock`, an expired `SYS_NOTIFICATION_WAIT` returns a zero
bitmask, a try-once that finds nothing ready returns `WouldBlock`, and a pending upcall refuses
only a park. Several threads can wait on one wait set. A receive resolves a bound sender's
CSpace from an identity copied at bind, so it no longer reads a caller's TCB that a canceller
can wake and free, and on x86_64 an xAPIC IPI is sent with interrupts disabled, so no interrupt
splits its ICR write pair. Every user leaf records the Write and Execute rights of the capability
that mapped it, and `SYS_MEM_PROTECT` and `THREAD_MEM_TEXT` writes are bounded by that grant.
An idle CPU's pull skips a backlog it cannot pull, the all-idle stall is reported only while
work waits undispatched, an aspace terminal fault is recorded before the thread's `Exited`, and
the x86_64 user-fault dump prints the #PF entry's cr2. Every riscv64 kernel frame is bounded at
2032 bytes, and the kernel's lint suppressions use `expect` with a reason. The bootloader counts
a memory range that ends at the top page when it bounds its page-table frames.

**Core services** (`services/`) — procmgr serves requests on a worker pool beside a reaper
thread, closes authority gaps on the debugger path, keeps an attach's debugger watch until its
reply is sent, and answers `QUERY_PROCESS` with `EXITED` once any thread of the process has taken
a terminal fault, before the reap. memmgr funds the client page-table pool on a demand-fault map.
svcmgr recognises the shutdown actuator by a declared key rather than a service name, and logs
its fatal bootstrap aborts at the error level. logd serves its endpoint from a receive pool,
frames structured fields, gives `seraph::log!` call sites their levels, holds its self-log lines
until init-logd releases the UART, and answers `QUERY_SLOTS` and `QUERY_HISTORY` over its slot
table and history. init serves the log handover labels only to real-logd's unbadged send.

**Drivers** (`services/devmgr`, `services/drivers/`) — devmgr binds drivers by their
declarations and from device records, serves every device class through one `QUERY_DEVICE`,
serves its registry from a pool of worker threads, and binds drivers on demand with
`BIND_DRIVERS`; a driver's instance limit counts every declaration of its name within one bind
pass. It gives a driver of a device that does DMA MSI or MSI-X vectors, writes the MSI-X table,
and programs VT-d interrupt remapping, which it leaves off, and logs why, when the remapping units
span more than one PCI segment or one was not handed over. It identity-maps firmware-reserved
ranges at IOMMU attach, keeps VT-d's interrupt range out of a device's IOVAs, refuses to confine a
device whose DMA width leaves no IOVA above 1 MiB, logs a VT-d interrupt-remapping fault by its
handle rather than as a DMA fault, and holds a bound device's resources on the heap. The CMOS RTC
driver binds to `PNP0B00`, `PNP0B01`, or `PNP0B02` as `_HID` or `_CID`, and takes the century
register from devmgr's device information (`device_info_kind::RTC_CENTURY`). The VirtIO drivers
use MSI-X and skip structures the transport cannot use. iommu-riscv maps a hart's IMSIC files
into a device's domain, and the VT-d driver changes one GCMD control field per write. The `edu`
device is attached only to test launches.

**Runtime** (`runtime/ruststd`, `shared/`) — Every `std` lock parks on the thread Parker with a
bounded fallback, `SERAPH_LOG` filters `seraph::log!`, and memmgr releases of demand regions
repeat when interrupted. A demand-paged thread stack has a four-page guard, a thread spawned
without a pager gets a guarded stack, and a page-table top-up lets the map decide whether it
covers the request. `shared/recv-pool` is a reusable worker-pool receive helper whose spawn
returns once its own workers have started, and the new `shared/driver-binding` crate encodes and
decodes driver declarations. `shared/elf` refuses a TLS template larger than its memory size. A
try-once call is not interrupted by a pending upcall, and the crash-report parser reads values
the format adds without a version bump.

**Userspace programs** (`programs/`) — The terminal queries the framebuffer class once, so a
boot with no framebuffer takes its serial-only path at once instead of after 100 queries.

**Build and test tooling** (`xtask`, CI) — `cargo xtask` applies the shared host's launch rules
itself, with a lock and a load check, and admits `cargo xtask test` under them; Ctrl+C ends a
wait for the host lock. The riscv64 host tests run under user-mode emulation, `lowuser` targets
emit inline stack probes, and test code is linted with `tests_outside_test_module` enforced. Owed
boots of four vCPUs or fewer run beside others, and nine defects recorded by the v0.1.3 release
review are fixed. The workspace lint table enforces the index and arithmetic, class A, and class
B lints, and std's dependencies are clippy-checked as workspace members.

**Documentation and project tooling** (`docs/`, `.claude/`) — The documents specify data-driven
driver binding, state the IMSIC file mapping devmgr owes message targets, and count a dead
module's deletion as an inert change. The review reports defects only, in bounded rounds, with one
release run, and the release scope is read from xtask in checked pages. The agent instructions
gain design-decision ownership rules and batch-state pruning.

## Breaking Changes

Every component named below ships in the one disk image, so an image consumer needs no
migration; code built outside the tree against v0.1.3 must be rebuilt against v0.1.4's `abi/`,
`shared/`, and `ruststd`.

- Hardware floor: the riscv64 kernel requires the AIA (Ssaia on every hart, the APLIC, and the
  IMSIC), and the PLIC is no longer supported. Under QEMU (9.0 or later) a riscv64 machine must
  be launched with `-machine virt,aia=aplic-imsic` and harts with `ssaia=on,smaia=on`.
  `BOOT_PROTOCOL_VERSION` 19 → 21 reports the APLIC and IMSIC and requires the `kernel_mmio`
  fields of the AIA.
- Init protocol: `INIT_PROTOCOL_VERSION` 16 → 17 states the root CSpace v0.1.3 already handed
  init without a bump: one body page, enough for init's first split, so init funds its own
  CSpace body arena before it splits further, and an init that does not fails its later splits
  with `OutOfMemory`. The kernel and init must come from the same release.
- Syscall contracts: `SYS_IPC_CALL` takes a `timeout_ms` in the high half of its third argument,
  with no try-once value; `SYS_IPC_RECV` and `SYS_WAIT_SET_WAIT` take a `timeout_ms` argument
  that accepts `WAIT_TRY_ONCE`; `SYS_NOTIFICATION_WAIT`'s `timeout_ms` gains `WAIT_TRY_ONCE`;
  `SYSCALL_NR_BOUND` moves to 65 with `SYS_IRQ_MSG_ALLOC`, `SYS_IRQ_ROUTE`, and `SYS_IRQ_REMAP`;
  a wired line's target is fixed by an explicit `SYS_IRQ_ROUTE`, not by its first binding;
  `SYS_MEM_PROTECT` and a `THREAD_MEM_TEXT` write refuse to go beyond the rights of the
  capability that mapped the page.
- Service protocols (`PROCMGR_LABELS_VERSION` 12 → 13, `DEVMGR_LABELS_VERSION` 15 → 18,
  `DEVMGR_DMA_LABELS_VERSION` 2 → 3, `IOMMU_LABELS_VERSION` 2 → 5, `STREAM_LABELS_VERSION`
  1 → 3, `LOG_LABELS_VERSION` 2 → 5): devmgr replaces its per-class queries
  (`QUERY_BLOCK_DEVICE`, `QUERY_SERIAL_DEVICE`, `QUERY_FRAMEBUFFER_DEVICE`, `QUERY_RTC_DEVICE`,
  `QUERY_INPUT_DEVICE`, `QUERY_DEBUG_PORT_DEVICE`) with `QUERY_DEVICE`, adds `MINT_CLASS_SEND`
  and `BIND_DRIVERS`, and retires its test labels; `BLOCK_DEVICE_AUTHORITY`,
  `DEBUG_PORT_AUTHORITY`, and `TEST_LABEL_AUTHORITY` give way to `CLASS_AUTHORITY` and
  `BIND_AUTHORITY`. logd adds `QUERY_SLOTS` and `QUERY_HISTORY`. Clients must use the v0.1.4
  `shared/ipc` labels.
- Image loading: `shared/elf` refuses a `PT_TLS` segment whose file size exceeds its memory size
  with `SegmentOverflow`, so an image carrying one no longer loads.

## Known Issues

- A service or driver tops up the shared page-table pool once and then maps once, so a top-up
  drawn by a concurrent map makes the map fail with `OutOfMemory`; in devmgr's `with_module` the
  failure releases a driver module or platform table that should have been read, and the system
  boots without it. Tracked by [#1032](https://github.com/kottlerg/seraph/issues/1032).
- `fund_cspace_slot_budget` returns false when the shared slot headroom still reads short after
  two rounds, so another thread's capability allocations can take the donated slots and make the
  call fail although every donation landed. Tracked by
  [#1033](https://github.com/kottlerg/seraph/issues/1033).
- `SYS_MEM_MAP` accepts a mapping at user virtual page 0, which gives a process the backing for a
  transient kernel null-pointer dereference at a small offset, one that SMAP or a clear
  `sstatus.SUM` stops only architecturally. Tracked by
  [#741](https://github.com/kottlerg/seraph/issues/741).
- On riscv64 no supervisor-mode hardware entropy source exists, so the entropy pool is seeded from
  timing jitter alone. Tracked by [#393](https://github.com/kottlerg/seraph/issues/393).
- Each virtio-blk transfer maps and unmaps the client's data segment through devmgr with two
  synchronous round trips, a per-request cost. Tracked by
  [#772](https://github.com/kottlerg/seraph/issues/772).
- `cargo xtask test-debug-port` repacks the disk images in the default layout for its staging
  and its restore, so after it a sysroot authored with 4096-byte blocks or a split data disk is
  left at 512-byte blocks with its data disk deleted. Tracked by
  [#1037](https://github.com/kottlerg/seraph/issues/1037).
- The `crasher` test fixture logs a failed svcmgr liveness probe without the `FATAL:` prefix, so
  a restart that re-injects a dead or stale svcmgr seed does not fail the run. Tracked by
  [#1038](https://github.com/kottlerg/seraph/issues/1038).
- When devmgr refuses an IOMMU driver that reported ready, its withdrawal deletes the driver's
  endpoint and starts a drain on the freed slot, so a later endpoint that reuses the slot has its
  calls answered with `HARDWARE_TIMEOUT` and their capabilities deleted. Tracked by
  [#1039](https://github.com/kottlerg/seraph/issues/1039).
- The IOMMU driver drops the count of faults lost during a `TAKE_FAULTS` poll, so those faults
  are never reported in its log. Tracked by
  [#1040](https://github.com/kottlerg/seraph/issues/1040).
- The FAT driver links a growing directory's new cluster before zeroing it, so a failed zeroing
  or a crash between the two writes leaves stale bytes in the directory that surface as ghost
  entries. Tracked by [#1041](https://github.com/kottlerg/seraph/issues/1041).
- usertest reads a tester's standard output to its end before its standard error, so a tester
  that writes more than the 2048-byte pipe ring to standard error while its standard output is
  open hangs the run until the boot's timeout. Tracked by
  [#1042](https://github.com/kottlerg/seraph/issues/1042).
- `cargo xtask pr-check` reads one Issue for each `Refs` keyword, so a line that lists several
  Issues after one keyword (`Refs #12, #34`) has only the first checked, and the gate passes
  without saying that the others were skipped. Tracked by
  [#1046](https://github.com/kottlerg/seraph/issues/1046).
- The ktest case `stress::irq_route_delete_race` requires a minimum share of its rounds to meet
  the race, which assumes the guest's CPUs run concurrently, so it fails on a host that
  oversubscribes them. The burn-in run for this tag failed its four ktest cells on this case
  alone, under CI load and with no kernel fault, and the release was published with that run red.
  Tracked by [#1048](https://github.com/kottlerg/seraph/issues/1048).
