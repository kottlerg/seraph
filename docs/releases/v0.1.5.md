A memory-governance, trust, and supervision release over v0.1.4: budget-node memory accounting with
swap, compressed eviction, and live process checkpoint and restore, a signed chain of trust from the
bootloader to every loaded object, supervised and restartable drivers and filesystems, ACPI and PCI
hotplug, and x86-64 transient-execution hardening.

---

## Highlights

- Memory governance: memmgr serves budget nodes with floors, weights, a create-time memory ceiling,
  a system reserve, pressure levels, and per-client charging of a server's state. It evicts cold
  chunks into a compressed store, seals them under a per-boot key for a swap slot that the new swapd
  service writes to disk, and commits heap growth as one region. oomd is a userspace out-of-memory
  policy service that stops a session's programs before services.
- Memory objects and checkpoints: memmgr serves immutable memory objects with shared and private
  attachments, so process instances share image pages. procmgr captures a live process with
  `SNAPSHOT`, quiesces it, and restores a checkpoint by an ordinary creation (`CREATE_RESTORE`).
  crashd writes an ELF core of a faulted process.
- Chain of trust: every object the system loads carries a composite Ed25519 and ML-DSA-65 signature,
  made once per role set. The bootloader verifies the kernel and every bundle entry before it parses
  them, configuration is read through signed indexes, and svcmgr and procmgr verify images before
  parse. The bootloader is signed for UEFI Secure Boot, keeps a persistent anti-rollback floor in a
  UEFI variable, and enrols and revokes roots without a rebuild. A signed setting can require DMA
  confinement.
- Supervision and restart: devmgr restarts a served driver that dies and the IOMMU driver beneath
  its units, vfsd restarts a dead non-root fs driver in place and unmounts on request, svcmgr gains
  stop sources, and sessiond runs in operator mode. Every supervised process's exit is reported by
  its one end, and an exit from any thread ends the address space (`SYS_ASPACE_EXIT`).
- Hardware: acpid serves ACPI AML evaluation, SCI, GPE and fixed events, and the power button, and
  devmgr handles PCIe native and ACPI PCI hotplug and routes INTx through each PCI-to-PCI bridge's
  `_PRT`. pwrmgr powers off (S5) and resets through acpid on x86-64, hardware-reduced platforms
  included. Entropy gains the hwrng class (virtio-rng, TPM 2.0), entropyd, and
  `SYS_ENTROPY_CONTRIBUTE`.
- Kernel hardening: x86-64 transient-execution mitigations (enhanced or automatic IBRS or
  retpolines, IBRS on entry for Retbleed, IBPB and DE_CFG on AMD), CET supervisor shadow stacks,
  riscv64 `sstateen0`, SMT-aware placement, a 64 KiB virtual floor for user mappings, and zeroed
  freed retype bytes.
- Filesystem sessions: every filesystem client opens its files in a session it pays for, found for a
  node capability with `SYS_ENDPOINT_IDENTIFY`, and fat gives idle cache pages back under memory
  pressure.
- Build tooling: `cargo xtask` has an in-tree command-line parser, JSON, GPT, FAT, and pattern
  engine in place of external crates, and its `test`, `run`, and `mkdisk` commands absorb the former
  separate commands.

## Components Shipped

**Kernel mechanisms** (`core/kernel`, `core/boot`) — New syscalls: `SYS_ENTROPY_CONTRIBUTE` (65),
`SYS_ASPACE_HARVEST` (66, with riscv64 software accessed and dirty emulation),
`SYS_THREAD_LIST_PAGES` (67), `SYS_THREAD_READ_EXT_REGS` (68), `SYS_ENDPOINT_BADGE` (69),
`SYS_MMIO_MERGE` (70), `SYS_ASPACE_HOLD` (71), `SYS_ASPACE_RELEASE` (72), and
`SYS_ENDPOINT_IDENTIFY` (73) with the endpoint Identify right; `SYSCALL_NR_BOUND` is 74. The exit
syscall is renamed `SYS_ASPACE_EXIT` (54) and ends the address space from any thread, and each
process has one exit reason. A call on an endpoint no receiver can serve fails, a debugger's fault
reply can redeliver to a named endpoint, and a call is atomic with upcalls. The kernel reads the
registers of a blocked thread, and on x86-64 reports a thread's TLS base in its register file. It
refuses user mappings below a 64 KiB virtual floor, re-links a dying CSpace's children under its
ancestors, posts an address space's death observers once, takes the x86-64 TSC rate from CPUID leaf
0x15 before the 8254, and gives a new thread the architected initial FP state. Security: x86-64
transient-execution vulnerabilities are enumerated and mitigated (enhanced or automatic IBRS or
retpolines for Spectre v2, IBRS on entry for Retbleed on Intel, IBPB and DE_CFG on AMD), CET
supervisor shadow stacks are enabled where the CPU has them and no selected control rewrites
returns, riscv64 harts write `sstateen0` and require Ssstateen, user-mode counter controls are
programmed on every CPU, freed retype bytes are zeroed, and the reseed seed is wiped. Scheduling
captures SMT topology and spreads placement across cores. The bootloader verifies the kernel and
every bundle entry's signature, refuses bundle entries out of offset order or sharing a page, keeps
an anti-rollback floor and an enrolled trust store in UEFI variables, logs the firmware's Secure
Boot state, and requires a bundle to carry the signed boot-time policy.

**Core services** (`services/`) — memmgr serves budget node handles with floors, weights,
proportional reclaim, a system reserve, and the pressure levels (`REGISTER_PRESSURE`), and charges a
grant to a donated node. It evicts cold chunks into a compressed store, restores them, backs commit
by swap slots, keeps incompressible chunks raw, and discards and trims heap ranges. It serves memory
objects with shared and private attachments, executable attachments, and per-region chunk tables.
procmgr records the process tree and destroys subtrees, captures a live process with `SNAPSHOT`,
quiesces a process, restores a checkpoint, reads a verified data file (`READ_VERIFIED`), verifies
every image before parse, takes a restarted logd's death-queue registration in place of the dead
instance's, and takes a create-time memory maximum. svcmgr adds stop authority, stop sources, a
program class, and a stoppable list, routes a death found before the bootstrap request or before
reconciliation, observes a worker-thread fault of a service whose address-space observer binds,
retries a restart refused for want of memory, and verifies configuration through signed indexes. A
stop source draws its keys from a value of each instance's own, so a key an earlier instance handed
out names a candidate of a later one only with a probability of at most about 2^-31. New services
are swapd, oomd, sessiond, and entropyd, and crashd writes ELF cores, from snapshots as well. vfsd
keeps a record of each mount, unmounts on request, restarts a dead non-root fs driver within a
restart budget, attaches a block device added after start, and handles the loss of a disk. logd is a
system-reserve service, takes its senders' names from init's handover after a restart until init's
reap, and bounds its history and sink waits. pwrmgr powers off (S5) and resets through acpid on
x86-64, a hardware-reduced platform included, and powers off on the death of a core service; svcmgr
powers off on the death of a critical one.

**Drivers** (`services/devmgr`, `services/drivers/`) — devmgr restarts a served driver that dies,
deciding on its process's exit reason, and restarts the IOMMU driver beneath its units, delivering
them to the new driver. It serves class change notifications, adds PCIe native hotplug and ACPI PCI
hotplug with slot discovery, withdraws and removes a slot's functions, places hot-added BARs within
the apertures, binds a hot-added disk from the drivers directory, merges returned Mmio spans, routes
an unprogrammed x86-64 INTx by the PIC-model `_PRT` of the root bus or of the nearest PCI-to-PCI
bridge that has its own, and reads a signed setting that requires DMA confinement. acpid serves ACPI
AML evaluation, `_OSC`, `_PRT` per root bus and per bridge, SCI, GPE and fixed events, and a
`RESET_REG` in memory space. New drivers are the TPM 2.0 GetRandom driver and virtio-rng, in the new
hwrng class. The serial and framebuffer drivers are debuggable.

**Storage** (`services/fs`) — fatfs opens every file in a session of its client, which pays for its
pages and reports a want of memory as `OUT_OF_MEMORY`. Its reads fill sequential misses in runs of
pages, idle cache pages return under memmgr's memory pressure, and a sparse write zero-fills its
gap. `FS_UNMOUNT` is added, and fatfs exits when its block capability is revoked.

**Runtime** (`runtime/ruststd`, `shared/`) — std opens each driver's files in one session found with
`SYS_ENDPOINT_IDENTIFY`, quiesces a process for a checkpoint, hands a spawned child bootstrap
capabilities, bounds a thread's calls by a call deadline, and recovers a CSpace with no free slot
from a reserve. A file operation on a node capability whose server is gone fails with
`StaleNetworkFileHandle`, and a checkpoint of a held address space with `WouldBlock`.
`shared/objsig` is the signed-object codec and verifier; `shared/crypto` adds Ed25519 signing,
ML-DSA-65, SHAKE, the ChaCha20-Poly1305 AEAD, and Wycheproof test infrastructure. `shared/aml` is
the AML parser and evaluator. `shared/ipc` moves each protocol module to its own source file.

**Userspace programs** (`programs/`, `services/gdbstub`) — The terminal runs through sessiond and
follows each driver class across a driver restart. The GDB stub reads the registers of a blocked
thread, resumes only the threads a `vCont` action names, and follows the debug port across a driver
restart. fsbench pins its timed reads to one CPU, and demandpaged gains a fault-cost bench mode.

**Build and test tooling** (`xtask`, CI) — `cargo xtask` parses its command line in-tree and
replaces clap, regex, serde_json, anyhow, fatfs, gpt, uuid, which, and ctrlc with in-tree code.
`test`, `run`, and `mkdisk` absorb the former per-case commands. xtask signs every object it
installs in the sysroot and the bootloader for Secure Boot, builds the trust store, writes trust
requests (`trust-request`), composes the ESP from installed files, strips installed images while
keeping their symbols by build id, loads symbols in GDB, and checks Rust formatting in build and
test instead of rewriting it. The ELF and DWARF crates come from the toolchain sysroot. CI gives
every `master` merge commit its own build-test run.

**Documentation and project tooling** (`docs/`, `.claude/`) — The documents specify the signing and
chain-of-trust design, the boot-media model, composite signatures, budget-node memory accounting,
cooperative checkpoint and restore, session supervision, the supervision hierarchy, and the
microarchitectural isolation posture. The project's instruction files run the pre-merge review while
CI runs.

## Breaking Changes

Every component named below ships in the one disk image, so an image consumer needs no migration;
code built outside the tree against v0.1.4 must be rebuilt against v0.1.5's `abi/`, `shared/`, and
`ruststd`.

- Signed images: every object is signed with the Ed25519 and ML-DSA-65 composite, by role set, and
  the bootloader verifies the kernel and every bundle entry before it parses them. An image or
  bundle that is unsigned, as every v0.1.4 image is, or signed by a key outside the trust store no
  longer boots. The bundle must carry the signed `/config/boot/policy.conf`, and its entries must
  lie in offset order with no two sharing a page. A machine whose anti-rollback floor a newer trust
  store has raised refuses an older image, its bootloader included. `BOOT_PROTOCOL_VERSION` 21 → 23,
  `INIT_PROTOCOL_VERSION` 17 → 19, and the bundle format `VERSION` 1 → 2 (entry names widen from 32
  to 256 bytes).
- Syscall contracts: the exit syscall `SYS_PROCESS_EXIT` is renamed `SYS_ASPACE_EXIT` (54) and ends
  the whole address space from any thread, so `std::process::exit` or a fatal receive failure on a
  spawned thread ends the process. `SYSCALL_NR_BOUND` moves from 65 to 74. A user mapping below a 64
  KiB virtual floor is refused. An IPC call on an endpoint no receiver can serve fails.
  `PROCESS_ABI_VERSION` 24 → 25 adds `restore_sp` to `ProcessInfo`.
- Service protocols (`PROCMGR_LABELS_VERSION` 13 → 26, `MEMMGR_LABELS_VERSION` 9 → 28,
  `SVCMGR_LABELS_VERSION` 10 → 16, `FS_LABELS_VERSION` 5 → 9, `VFSD_LABELS_VERSION` 2 → 4,
  `DEVMGR_LABELS_VERSION` 18 → 30, `IOMMU_LABELS_VERSION` 5 → 6, `PWRMGR_LABELS_VERSION` 1 → 3,
  `STREAM_LABELS_VERSION` 3 → 4): clients must use the v0.1.5 `shared/ipc` labels. fatfs refuses an
  `FS_OPEN` made outside a session its client pays for, so every file open goes through a session
  opened with the node capability.
- Boot configuration: devmgr reads its `dma-confinement` setting from the signed boot-time policy;
  the default, `opportunistic`, keeps the earlier behaviour, and `required` gives no driver to a
  DMA-capable device that no IOMMU unit confines.
- Build tooling: `cargo xtask` drops the separate `test-*`, `run-parallel`, `compose-bundle`, and
  `review-check` commands, which `test`, `run`, `mkdisk`, and `review-ledger` absorb.

## Known Issues

- Each virtio-blk `BLK_READ_INTO_MEMORY` or `BLK_WRITE_FROM_MEMORY` transfer maps and unmaps the
  client's data segment through devmgr, which adds two synchronous round trips per request. Tracked
  by [#772](https://github.com/kottlerg/seraph/issues/772).
- std's `File::open` with `create` set can leave an empty file behind when the open itself is then
  refused for want of the process's memory, since the create and the open are separate requests.
  Tracked by [#TBD-ISSUE](https://github.com/kottlerg/seraph/issues/TBD-ISSUE).
