# Every help screen of xtask's command table, recorded from the clap 4.6
# derive parser at 9c8b0c7a0, before the in-tree parser replaced it
# (xtask/src/argparse/reference.rs): `-h` and `--help` of each command, and
# `help help`. A screen runs from its `=== <name>` line to the next;
# cases.txt names the screens. `XTASK_BLESS_REFERENCE=1 cargo xtask test`
# rewrites them from the current table.

=== xtask -h
Seraph build task runner — invoke via `cargo xtask`

Usage: xtask <COMMAND>

Commands:
  build           Build Seraph components and populate the sysroot
  run             Boot Seraph under QEMU against the populated sysroot (run `cargo xtask build` first): one interactive boot, or with `--runs N` N unattended boots, each classified by its log
  clean           Remove the sysroot, the symbols store and the disk images (and with `--all` cargo's target/)
  test            Run Seraph's tests: without a case, check formatting and lint the test code, then run the unit tests on the host and, built for riscv64, under QEMU's user-mode emulator; with a CASE, boot the current sysroot for that host-driven QEMU case; with `--cell`, run every case a CI validate cell runs (see xtask/README.md)
  crypto-vectors  Regenerate the reference vectors of shared/crypto/testkit with OpenSSL, or with `--check` fail unless they regenerate identically
  fuzz            Build the fuzz targets with coverage instrumentation and run one, or with `--all` each, under the in-tree engine for an execution budget or a time; replay one input, minimize a corpus, list the targets, or with `--self-test` check that the engine finds its planted defects reproducibly. Exits non-zero when an input fails, with its report under target/xtask/fuzz/<target>/crashes/ (see xtask/README.md)
  kani            Run the Kani proof harnesses (`#[cfg(kani)] mod proofs`) of every crate that holds one, with the pinned Kani release, and fail on any failed, undetermined or unwinding-incomplete check, on a Kani release other than the pinned one, and on a harness in an unregistered crate; with `--pin`, print the pinned release (see xtask/README.md)
  ktest-timing    Read preserved ktest boot logs (from `run --runs N --save-logs`) and print per-tier and per-cell wall times; with `--base` and `--wide`, compare two widths against their width factor; with `--baseline`, compare one log against a checked-in baseline of the same width; with `--write-baseline`, write one. Report-only: a flagged row never fails the command. See xtask/README.md for the tables and the baseline format
  bench-check     Compare the benchmark result lines of saved run logs (from `run --runs N --save-logs`) with the checked-in baselines of their mode and architecture: each measurement's lowest p50 over the runs against its stored p50 and band. Icount mode fails on a one-CPU measurement past its band in either direction, one with no baseline or no run, and a benchmark's FAIL line; host mode reports only. See xtask/README.md for the rules and the file formats
  bench-baseline  Rewrite the benchmark baselines from the bench cell's artifacts of a CI run (icount mode), or from saved logs of this host (host mode): each baseline file whose measurements moved past their bands, appeared or went, or every file with `--all`. See xtask/README.md
  symbolize       Resolve runtime addresses in a loaded ELF image (a binary, or the sysroot's kernel) to function, file, and line from its DWARF, or to the nearest function symbol when no DWARF covers an address; a stripped image's symbols are the symbols store's file of its build id. Each output line names the source it used. With `--log`, print every crash-report block of a serial log with its addresses resolved against the sysroot's binaries. See xtask/README.md
  mkdisk          Mirror `rootfs/` into the sysroot, re-synthesise test fixtures, choose the harness, the bootloader knobs and the log-level configuration the image boots, and regenerate `disk.img` without invoking cargo. The mirror is authoritative over `config/`+`data/` (deletions in `rootfs/` are pruned); use `--repack-only` to pack a hand-staged sysroot without it (the repository's data files, the log-level configuration among them, are installed either way; pack another configuration with `--log-levels`). Every pack re-signs the sysroot's signed objects in place, then checks the images it wrote with `fsck.fat -n` (dosfstools) and reads their ESP back against the root partition. Requires an arch-tagged sysroot from a prior `cargo xtask build`
  trust-request   Write a trust request: roots to enrol and key ids to revoke in the trust store the bootloader keeps in firmware storage, signed by the build's signing identity in the enrolment role or unsigned, for the console to confirm. Staged in the sysroot's ESP for the next pack, or written to a file to copy onto a machine's ESP as `\EFI\seraph\trust-request` (see xtask/README.md)
  capture-acpi    Capture the ACPI tables of one QEMU configuration into the `shared/aml` fixtures: boot the firmware alone on a blank disk, save the guest's memory over QMP once the firmware has installed its tables, find the RSDP, walk the XSDT, and write the DSDT and every SSDT with a note of the capture (see xtask/README.md)
  lint-docs       Check the mechanical documentation and source-header rules: Markdown column limit, file-header layout, `## Summarized By` shape, forward links, order, and labels, and document reachability from the root README. Runs in CI's host-tests job; see xtask/README.md for the rule list and levels
  commit-check    Check the commits of a range against the commit-message rules of docs/conventions.md: subject form and width, Issue references and planning labels in the subject, closing keywords, attribution, and signatures. Runs in CI's host-tests job on a pull request; see xtask/README.md for the rule list and levels
  pr-check        Check a pull request against the rules of docs/conventions.md a script can decide: its commits, its body's boxes and validated head, its milestone, and the Issues it closes or references; with `--gate`, the merge gate too. Reads GitHub through `gh` (see xtask/README.md)
  compare-images  Build two commits (by default the merge base with `origin/master` and `HEAD`) for each architecture and profile in one scratch worktree, and compare every installed image in the parts a loader reads; print each image and part that differs and a verdict line, and fail when one differs (see xtask/README.md)
  review-ledger   Validate the saved run records of a pull request's pre-merge review (`target/xtask/review/pr<N>/`) against the record shape and build `ledger.json` from them, or print a release review's ledger for the files named: the findings a later run must not re-raise (see xtask/README.md)
  release-scope   Print the scope of a release review as JSON, in pages of bounded size with a digest each: the range's files, its first-parent units and their files, and the open Issues (see xtask/README.md)
  issue-edit      Replace a GitHub Issue's body from a file, refusing an empty body or one that lost task-list items, keeping a backup, and verifying the edit (see xtask/README.md)
  issue-file      File a GitHub Issue with the labels and milestone docs/conventions.md requires, and verify that both were applied (see xtask/README.md)
  orch            Keep the on-disk state of an orchestration batch (`target/xtask/orchestration/state.json`) and its log: the orchestrator, the exclusive grant, the workers, the merge order, the open questions and the rulings in force. `orch state` prints it (see xtask/README.md)
  host            Show the shared host's state as the launch rules read it: the load, the exclusive grant, the commands holding the host, and the QEMUs running (see xtask/README.md "Host launch rules")
  hook            Answer a hook of the assistant's harness: read the event's JSON on stdin and print the answer the harness reads. `.claude/settings.json` names these commands (see xtask/README.md)
  help            Print this message or the help of the given subcommand(s)

Options:
  -h, --help  Print help

=== xtask build -h
Build Seraph components and populate the sysroot

Usage: xtask build [OPTIONS]

Options:
      --arch <ARCH>            Target architecture [default: x86_64] [possible values: x86_64, riscv64]
      --release                Build in release mode (default: debug)
      --component <COMPONENT>  Build only one component (default: all): `boot`, or the crate name of any component the build installs [default: all]
      --debug <DEBUG>          Emit debuginfo (`debug = 2`, `opt-level = 1`) for the named component(s) only, within the active profile (default or `--release`). Comma-separated, e.g. `--debug kernel,procmgr`; names match `--component`. Only components in the current build are affected
      --ktest-bench-only       Build ktest with its `bench-only` feature: the benchmark tier alone, each benchmark at its full iteration count, for a run whose result lines are compared (core/ktest/README.md "Tier 3"). Needs a build that includes ktest (`--component all` or `ktest`)
      --wait-host <SECS>       When the host refuses this command, wait up to SECS for it to admit it, asking again every 10 s, instead of failing at once; at the bound the command fails with the last refusal
      --host-override          Start even when the host's rules refuse, printing the refusal: for the maintainer's interactive use. A boot still registers, so other commands see it
  -h, --help                   Print help (see more with '--help')

=== xtask run -h
Boot Seraph under QEMU against the populated sysroot (run `cargo xtask build` first): one interactive boot, or with `--runs N` N unattended boots, each classified by its log

Usage: xtask run [OPTIONS]

Options:
      --arch <ARCH>
          Target architecture [default: x86_64] [possible values: x86_64, riscv64]
      --cpus <CPUS>
          Number of vCPUs to expose to the guest (QEMU -smp) [default: 4]
      --threads-per-core <THREADS_PER_CORE>
          Logical CPUs per core in the guest's topology (QEMU `-smp <cpus>,threads=<n>`); must divide `--cpus`. 2 presents SMT sibling pairs, which the kernel's placement spreads threads across (core/kernel/docs/scheduler.md "SMT Awareness"); riscv64 takes each hart as a core of its own whatever this says [default: 1]
      --mem <MEM>
          Guest memory size in MiB (QEMU -m) [default: 512]
      --riscv-mmu <RISCV_MMU>
          Guest RISC-V paging-mode ceiling (riscv64 only; ignored on `x86_64`). The kernel negotiates the highest advertised mode at boot, so this selects the mode a run exercises [default: sv48] [possible values: sv39, sv48, sv57]
      --riscv-zkr <RISCV_ZKR>
          Whether the guest RISC-V CPU implements the Zkr entropy source (riscv64 only; ignored on `x86_64`). `off` boots the kernel's hardware-RNG path without a source: its probe of the `seed` CSR traps and the pool seeds from the firmware boot seed and jitter [default: on] [possible values: on, off]
      --x86-paging <X86_PAGING>
          Guest x86-64 paging depth (`x86_64` only; ignored on riscv64). Pins the QEMU CPU's `la57` property; the bootloader enables 5-level paging when CPUID reports LA57, so this selects the depth a run exercises [default: 4] [possible values: 4, 5]
      --x86-shadow-stack <X86_SHADOW_STACK>
          Whether the guest x86-64 CPU offers CET supervisor shadow stacks (`x86_64` only; ignored on riscv64). Pins the QEMU CPU's `cet-ss` property, so the host's CPU never decides it; a QEMU without the property cannot offer them and gets no pin. `on` boots the kernel on shadow stacks, or refuses to boot when the accelerator or the QEMU cannot offer them; the cet cell (`cargo xtask test cet`) is where they are tested [default: off] [possible values: off, on]
      --iommu <IOMMU>
          Whether the machine's IOMMU is attached, with the driven `virtio-pci` devices behind it. `absent` boots the no-IOMMU variant, the no-iommu device cell of the local and release host runs (docs/testing.md "Coverage tiers"), which keeps devmgr's unconfined path covered while the attached IOMMU confines every device a driver binds [default: attached] [possible values: attached, absent]
      --second-disk <PATH>
          Attach this image as a second disk: its own `virtio-blk-pci` device (drive `hd1`) beside `disk.img`, presenting the logical block size of the image's GPT unless `--second-disk-block-size` sets it (an image with no GPT at 512- or 4096-byte blocks needs it set). `cargo xtask mkdisk --split-data` authors `disk-data.img` for it
      --second-disk-block-size <BYTES>
          Logical and physical block size, in bytes, of the second disk's device, overriding the size read from its image (a power of two of at least 512; a size above the guest driver's 4096 stages the boot whose second device the driver refuses)
      --second-disk-shared-line
          Place the second disk's device on the first disk's `INTx` line (four PCI slots past it, where both machines' interrupt routing puts it on the same line), and launch both disks with no MSI-X, staging the boot in which two virtio-blk devices share one line
      --debug-port <PORT>
          Attach the debug port: a `virtio-serial-pci` device with one `virtconsole` port, which devmgr binds as the debug port, its host end a TCP server QEMU listens with on `127.0.0.1:<PORT>` (a debugger connects with `target remote localhost:<PORT>`). The console keeps the UART
      --debug-target <NAME>
          Stage the GDB stub for this boot, attached to the process named NAME (its argv[0]), and print the GDB command line that connects to it; the stub is unstaged when QEMU exits. Requires `--debug-port`
      --test-devices
          Attach the test devices svctest's devmgr phases drive through the test-only drivers: QEMU's `edu` device and five `pci-testdev` functions. A svctest boot needs them (docs/testing.md § Gating)
      --icount
          Count instructions: run the machine on single-threaded TCG with QEMU's `-icount shift=0,sleep=off,align=off`, so the guest's clock and cycle counters advance one tick per retired instruction, the deterministic measure `bench-check --mode icount` compares. Always TCG; on `x86_64` the CPU model drops x2APIC, whose timer QEMU's icount cannot serve, so the kernel runs its xAPIC paths
      --runs <N>
          Boot N times unattended and classify each run's log as PASS, FAIL, HANG, OK, ERR or QEMU-CRASH by the `--pass` and `--fail` patterns, failing unless every run passes (a QEMU-CRASH is tolerated). Without it, `run` is one interactive boot whose serial output is the terminal's
      --display <DISPLAY>
          What the guest presents for display. `window` attaches QEMU std VGA and shows it in a window; `framebuffer` attaches it with no window (`-display none`), so the framebuffer driver runs on a host without a graphical backend: the framebuffer device cell of the local and release host runs (docs/testing.md "Coverage tiers"); `headless` attaches no adapter, so the bootloader finds no GOP and devmgr spawns no framebuffer driver. Default: `window` for the interactive boot, `headless` with `--runs`, which refuses `window` [possible values: window, framebuffer, headless]
      --gdb
          Start QEMU with a GDB server on localhost:1234, paused at startup (QEMU `-s -S`). Interactive boot only
      --debug-listen
          Expose the guest's gdbstub on localhost:1234 without pausing it (QEMU `-s`), so a wedged guest can be attached to post hoc: `gdb -ex 'target remote :1234'`. With `--runs`, requires `--parallel 1` (one gdbstub port)
      --verbose
          Show all serial output including pre-boot firmware noise (suppressed by default). Interactive boot only
      --parallel <PARALLEL>
          Concurrency of `--runs`: number of QEMU instances in flight at once; the runs are dispatched in waves of this many [default: 1]
      --timeout <TIMEOUT>
          Per-run timeout of `--runs`, in seconds. A run still alive at this point is killed and classified as HANG [default: 30]
      --pass <PASS>
          Regex marking a successful run of `--runs`. On match (and every `--require` and `--crash-reports` check holding) the log is discarded and the run is classified PASS. The default matches the cross-harness terminal marker `[<harness>] ALL TESTS PASSED` standardised in [`docs/testing.md`](../../docs/testing.md); override for other rootfs configurations [default: "ALL TESTS PASSED"]
      --fail <FAIL>
          Regex marking a failed run of `--runs`. On match the log is preserved as FAIL-<run>.log. Failure takes precedence over success. The default matches the cross-harness terminal marker `[<harness>] SOME TESTS FAILED` ([`docs/testing.md`](../../docs/testing.md)) plus the kernel's own death markers, so a crash classifies as FAIL rather than HANG: a hardware trap prints `KERNEL EXCEPTION` then `FATAL:` (`core/kernel/src/main.rs` `fatal()`), a Rust `panic!` prints `PANIC at`/`PANIC:` (the `#[panic_handler]`), and the scheduler's wedge detectors print a dump headed `=== WATCHDOG` (a kernel that detected its own stall is a failure, not a hang), and the entropy subsystem's boot self-test prints `entropy: SELFTEST FAIL`. The benign userspace fault path prints `USERSPACE FAULT`, which none of these match. Override with a never-matching pattern (e.g. `'$.^'`) to disable [default: "SOME TESTS FAILED|KERNEL EXCEPTION|FATAL:|PANIC( at |: )|=== WATCHDOG|entropy: SELFTEST FAIL"]
      --fail-also <REGEX>
          A further regex marking a failed run of `--runs`, matched beside `--fail` rather than in its place, so the default's death markers still apply: a run whose log matches either is FAIL, with the same precedence and `--fail-grace-secs` kill. The framebuffer device cell passes `'framebuffer case skipped'`, the line svctest logs when no framebuffer driver runs
      --require <REGEX>
          A regex a line of the log must match for a run of `--runs` to pass; repeatable, each must match. A run whose `--pass` pattern matched but whose log has no line matching one of these is FAIL, naming the pattern
      --crash-reports <CRASH_REPORTS>
          Check the crash service's report blocks in each passing run's log: every block well-formed, and `reports` the `crashme` fixture's three reports, `none` no block at all. A run whose check fails is FAIL; a QEMU-CRASH run is not checked [possible values: reports, none]
      --hold-on-hang
          On a hard-timeout HANG of `--runs`, do not kill the QEMU instance: print the attach instructions and block until it is terminated externally, preserving the wedged guest for inspection (pair with `--debug-listen`). Requires `--parallel 1`
      --fail-grace-secs <FAIL_GRACE_SECS>
          Grace window of `--runs`, in seconds, after the first `--fail` match before the run is `SIGKILLed`. A kernel fault dump is multi-line and may be followed by secondary-CPU faults; killing on the first matching byte truncates the diagnostics. The run is killed at whichever is first: this window, or the `--timeout` deadline. 0 kills on the next poll after the match [default: 10]
      --save-logs <DIR>
          Also copy every run's log of `--runs`, whatever its outcome, to `<DIR>/<arch>-<cpus>cpu-<run>.log`, ending with a `[run]` trailer line that records the run's arch, width, accelerator, whether it counted instructions (`icount=`), outcome, and host wall time. DIR is created if absent and never purged; a file of the same name is overwritten
      --wait-host <SECS>
          When the host refuses this command, wait up to SECS for it to admit it, asking again every 10 s, instead of failing at once; at the bound the command fails with the last refusal
      --host-override
          Start even when the host's rules refuse, printing the refusal: for the maintainer's interactive use. A boot still registers, so other commands see it
      --alone
          Run beside no other QEMU, and keep every other boot off the host while it runs: the re-run of a boot whose timeout or timing failure came beside another QEMU, before that failure counts
      --timing
          A timing-sensitive measurement: run beside no other QEMU, under the load limit of 10 of a boot that needs the host to itself, and refuse builds while it runs
      --grant <HOLDER>

          [default: 30]

          Regex marking a successful run of `--runs`. On match (and every `--require` and `--crash-reports` check holding) the log is discarded and the run is classified PASS.           [default: "ALL TESTS PASSED"]

      --fail <FAIL>
          Regex marking a failed run of `--runs`. On match the log is preserved as FAIL-<run>.log. Failure takes precedence over success.       --fail-grace-secs <FAIL_GRACE_SECS>
          Grace window of `--runs`, in seconds, after the first `--fail` match before the run is `SIGKILLed`. The run is killed at whichever is first: this window, or the `--timeout` deadline. 0 kills on the next poll after the match
          
          [default: 10]

      --save-logs <DIR>
          Also copy every run's log of `--runs`, whatever its outcome, to `<DIR>/<arch>-<cpus>cpu-<run>.log`, ending with a `[run]` trailer line that records the run's arch, width, accelerator, whether it counted instructions (`icount=`), outcome, and host wall time. DIR is created if absent and never purged; a file of the same name is overwritten

      --wait-host <SECS>
          When the host refuses this command, wait up to SECS for it to admit it, asking again every 10 s, instead of failing at once; at the bound the command fails with the last refusal

      --host-override
          Start even when the host's rules refuse, printing the refusal: for the maintainer's interactive use. A boot still registers, so other commands see it

      --alone
          Run beside no other QEMU, and keep every other boot off the host while it runs: the re-run of a boot whose timeout or timing failure came beside another QEMU, before that failure counts

      --timing
          A timing-sensitive measurement: run beside no other QEMU, under the load limit of 10 of a boot that needs the host to itself, and refuse builds while it runs

      --grant <HOLDER>
          Boot under the exclusive grant `cargo xtask orch grant set` gave HOLDER. While a grant is outstanding, a boot that does not name its holder is refused

  -h, --help
          Print help (see a summary with '-h')

=== xtask mkdisk -h
Mirror `rootfs/` into the sysroot, re-synthesise test fixtures, choose the harness, the bootloader knobs and the log-level configuration the image boots, and regenerate `disk.img` without invoking cargo. The mirror is authoritative over `config/`+`data/` (deletions in `rootfs/` are pruned); use `--repack-only` to pack a hand-staged sysroot without it (the repository's data files, the log-level configuration among them, are installed either way; pack another configuration with `--log-levels`). Every pack re-signs the sysroot's signed objects in place, then checks the images it wrote with `fsck.fat -n` (dosfstools) and reads their ESP back against the root partition. Requires an arch-tagged sysroot from a prior `cargo xtask build`

Usage: xtask mkdisk [OPTIONS]

Options:
      --arch <ARCH>              Target architecture — must match the existing sysroot's arch tag [default: x86_64] [possible values: x86_64, riscv64]
      --repack-only              Repack `disk.img` from the sysroot as it stands, skipping the `rootfs/` re-mirror; the repository's data files are still installed, and the sysroot's signed objects re-signed in place, as every pack signs them. Use after editing the staged sysroot directly (e.g. adding a test recipe or removing a default one): a normal re-mirror is authoritative and would restore `rootfs/`-present recipes and prune `rootfs/`-absent ones, undoing the manual staging
      --harness <HARNESS>        Record the harness whose bundle this and every later pack composes from the installed files its bundle list names: `init` for the userspace init, `ktest` for the kernel-test harness. Omit to keep the recorded harness (`init` after `cargo xtask build`) [possible values: init, ktest]
      --knob <KNOB>              Stage a bootloader knob in `\EFI\seraph\`: `nokaslr` boots the kernel at its deterministic (un-randomized) layout, for GDB and symbolization; `mapredo` makes the bootloader redo the first attempt of its steps 6 and 7. Repeatable, or comma-separated. The image carries exactly the knobs named: every other is removed [possible values: nokaslr, mapredo]
      --log-levels <FILE>        Install FILE as the log-level configuration init reads (`/config/init/log-levels.conf`) in place of the repository's `services/init/log-levels.conf`, which mkdisk installs without it. Refused unless init's parser accepts every line
      --block-size <BLOCK_SIZE>  Logical block size of the authored images: the unit of their GPT LBAs and the sector size of their FAT volumes. `run` and the other launchers present the disk device at the size the image's GPT has [default: 512] [possible values: 512, 4096]
      --split-data               Author the data partition alone on a second image, `disk-data.img`, and only the ESP, root and swap partitions on `disk.img`; boot the pair with `--second-disk disk-data.img`. Without it `disk.img` carries all four and a `disk-data.img` an earlier authoring left is removed
